# Agent Hooks 0.7.0

Supply-chain, packaging, and honesty-of-documentation release. No public type, method, or
dispatch behavior was removed or renamed; the 0.6.x event, decision, and registry API is
source- and binary-compatible. Two methods were added to `AgentHookBridge`.

## Consumer dependency closure

The 0.6.x published child POMs did not protect a consumer that resolves a module without
importing a BOM. Maven `dependencyManagement` in the parent does not travel through the
flattened POM that reaches Maven Central, so a standalone consumer of `agent-hooks-spring`
selected `tools.jackson.core:jackson-core` **3.0.3** and `jackson-databind` **3.1.4**, and a
standalone consumer of `agent-hooks-gemini` selected `com.fasterxml.jackson.core`
**2.21.2** — versions with known advisories.

0.7.0 raises the reactor floors to Jackson **2.21.6** and **3.1.6**, and declares the
Jackson 3 floor directly on `agent-hooks-spring` so nearest-wins protects a no-BOM consumer.
All four published modules now resolve at or above those floors on their own.

## Published POMs no longer carry repositories

0.6.x published a `<repositories>` block on every module POM, so every downstream consumer
inherited `repo.spring.io/milestone`, `repo.spring.io/snapshot`, and the Central snapshot
repository. Those are gone; the build resolves from Maven Central alone.

## Claude Agent SDK

`claude-code-sdk` moves from 1.2.0 to **1.4.0**, matching the version the AgentWorks BOM
pins for consumers. It remains `provided` scope — you supply the SDK.

## Build and supply chain

- The reactor root now produces one aggregate CycloneDX 1.6 SBOM (`agent-hooks-bom.json`);
  child modules produce none.
- Reusable GitHub workflows are pinned to an immutable `build-tools` commit instead of the
  mutable `@main`. CI gained a manual dispatch trigger.
- The hosted OWASP/NVD `security.yml` workflow and the `owasp` Maven profile are removed.
  Vulnerability scanning is a local, offline step against a database snapshot you have
  validated and frozen: see `scripts/security-scan.sh`.
- The compiler uses `maven.compiler.release=17` rather than `source`/`target`, so building
  on a newer JDK cannot silently admit a post-17 API.

## Behavior and documentation corrections

- `AgentHookRegistry` now logs, at `WARNING` via `java.util.logging`, both an exception
  thrown by a hook and a steering decision returned from an observation-only event. Both
  were already documented as logged and were in fact silent — a security hook that threw
  degraded to `Proceed` with no signal at all.
- The Gemini dispatcher now writes a protocol response for **every** invocation. Previously
  an unchecked failure in a hook or in the registry could exit the process with nothing on
  stdout, leaving the CLI waiting.
- Warning and exception messages in the Gemini and Claude adapters no longer embed tool
  input payloads, which routinely carry credentials.
- `AgentHookBridge` gained `evictSession(String)` and `activeSessionCount()`. The bridge
  retains one `HookContext` per Claude session id for its own lifetime; a long-lived bridge
  shared across sessions now has a supported way to release them.
- Javadoc now states three things that were previously implied but untrue or unstated:
  `HookDecision.Retry` is **advisory** — no shipped adapter re-executes the tool; the
  registry dispatches on the event's **exact runtime class**, so a hook registered on a
  supertype never fires; and the Spring auto-configuration's default `HookContext` is an
  **application-wide singleton**, which is wrong for a multi-user server.
- The repository gained a README. `CLAUDE.md` no longer describes Spring milestone versions
  or calls `io.github.markpollack` a candidate coordinate.

## Compatibility

Java 17. Spring AI 2.0.0, Spring Boot 4.0.7, Claude Agent SDK 1.4.0.
